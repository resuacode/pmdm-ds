# Corrutinas en Unity

Vamos a ver qué son las corrutinas en Unity y cómo funcionan. Las corrutinas permiten repartir la ejecución de una función a lo largo de varios frames: puedes pausar su ejecución y reanudarla más tarde sin congelar el juego. Ojo, no se ejecutan en otro hilo: todo sigue ocurriendo en el hilo principal, pero la función "cede el turno" en cada pausa para que el resto del juego pueda seguir funcionando.
Esto es útil para tareas que requieren esperar un tiempo determinado, como animaciones, temporizadores o esperas entre acciones.

## ¿Qué son las corrutinas?

Las corrutinas son funciones que pueden pausar su ejecución y reanudarla en un momento posterior. En Unity, las corrutinas se implementan como métodos cuyo tipo de retorno es `IEnumerator` (del espacio de nombres `System.Collections`). Dentro de ellos, la instrucción `yield return` indica dónde se pausa la ejecución y hasta cuándo. Para ponerlas en marcha se usa `StartCoroutine()`, que devuelve un objeto `Coroutine` que representa la ejecución de la corrutina y que podemos usar para detenerla con `StopCoroutine()`.   

:::warning[No llames a la corrutina directamente]
Si escribimos `MiCorrutina();` en lugar de `StartCoroutine(MiCorrutina());`, el código compila pero **no se ejecuta nada**. Es uno de los errores más habituales al empezar con corrutinas.
:::

## ¿Cómo funcionan?

Para crear una corrutina, debes definir una función que devuelva un `IEnumerator`. Dentro de la función, puedes usar la palabra clave `yield` para pausar la ejecución y devolver un valor. Por ejemplo, puedes usar `yield return null` para pausar la ejecución hasta el siguiente fotograma o `yield return new WaitForSeconds(2)` para pausar la ejecución durante 2 segundos.
Aquí tienes un ejemplo de una corrutina que espera 2 segundos antes de imprimir un mensaje en la consola:

```csharp
using System.Collections;
using UnityEngine;

public class CorrutinaEjemplo : MonoBehaviour
{
    // Método que inicia la corrutina
    public void IniciarCorrutina()
    {
        StartCoroutine(MiCorrutina());
    }

    // Corrutina que espera 2 segundos antes de imprimir un mensaje
    private IEnumerator MiCorrutina()
    {
        Debug.Log("Esperando 2 segundos...");
        yield return new WaitForSeconds(2);
        Debug.Log("¡2 segundos han pasado!");
    }
}
```

En este ejemplo, al llamar al método `IniciarCorrutina`, se inicia la corrutina `MiCorrutina`, que espera 2 segundos antes de imprimir el mensaje "¡2 segundos han pasado!" en la consola.  

Las instrucciones de espera más habituales son:

- `yield return null;`: espera al siguiente frame.
- `yield return new WaitForSeconds(t);`: espera `t` segundos de tiempo de juego (se ve afectado por `Time.timeScale`, por lo que se detiene si pausamos el juego poniéndolo a 0).
- `yield return new WaitForSecondsRealtime(t);`: espera `t` segundos reales, aunque el juego esté pausado.
- `yield return new WaitForFixedUpdate();`: espera al siguiente paso de físicas.
- `yield return new WaitUntil(() => condicion);`: espera hasta que se cumpla una condición.
- `yield return StartCoroutine(OtraCorrutina());`: espera a que termine otra corrutina.

Las corrutinas se detienen automáticamente si se destruye o desactiva el GameObject que las lanzó. También podemos detenerlas nosotros con `StopCoroutine(corrutina)` o detener todas las del script con `StopAllCoroutines()`.

## Ejemplo práctico

Vamos a crear un ejemplo práctico de una corrutina que hace que un objeto se mueva de un punto a otro en la escena. Para ello, crearemos un script que moverá un objeto de su posición actual a una nueva posición en 2 segundos.

```csharp
using System.Collections;
using UnityEngine;

public class MoverObjeto : MonoBehaviour
{
    public Transform objetivo; // El objeto al que queremos movernos
    public float tiempoMovimiento = 2f; // Tiempo que tardará en moverse

    // Método que inicia la corrutina
    public void Mover()
    {
        StartCoroutine(MoverAObjetivo());
    }

    // Corrutina que mueve el objeto a la posición del objetivo
    private IEnumerator MoverAObjetivo()
    {
        Vector3 posicionInicial = transform.position;
        Vector3 posicionFinal = objetivo.position;
        float tiempoTranscurrido = 0f;

        while (tiempoTranscurrido < tiempoMovimiento)
        {
            transform.position = Vector3.Lerp(posicionInicial, posicionFinal, tiempoTranscurrido / tiempoMovimiento);
            tiempoTranscurrido += Time.deltaTime;
            yield return null; // Espera hasta el siguiente fotograma
        }

        transform.position = posicionFinal; // Asegúrate de que el objeto llegue a la posición final
    }
}
```

En este ejemplo, al llamar al método `Mover`, se inicia la corrutina `MoverAObjetivo`, que mueve el objeto de su posición actual a la posición del objeto `objetivo` en 2 segundos. La función `Vector3.Lerp` se utiliza para interpolar entre las dos posiciones a lo largo del tiempo.

## Las corrutinas en Unity 6

Las corrutinas clásicas (`IEnumerator`) siguen funcionando exactamente igual en Unity 6 y siguen siendo una opción válida y útil para muchas situaciones.

Sin embargo, desde Unity 2023.1 (y por tanto en Unity 6) existe una alternativa basada en las palabras clave `async` y `await` de C# moderno: la clase **`Awaitable`**, del espacio de nombres `UnityEngine`. Su uso es completamente opcional, pero permite escribir el mismo código de una forma más secuencial y es la forma natural de combinar la lógica del juego con otras operaciones asíncronas, como descargas o lecturas de ficheros.

Vamos a ver un ejemplo que agrega un comportamiento visual cuando un jugador recibe daño usando una corrutina que hace que parpadee el sprite del jugador.

- Con IEnumerator:

```csharp title="DamageEffect.cs"
using System.Collections;
using UnityEngine;

public class DamageEffect : MonoBehaviour
{
    private SpriteRenderer sr;
    public float flashDuration = 0.1f;
    public int flashCount = 5;

    void Awake()
    {
        sr = GetComponent<SpriteRenderer>();
    }

    public void TriggerFlash()
    {
        StartCoroutine(FlashRoutine());
    }

    private IEnumerator FlashRoutine()
    {
        for (int i = 0; i < flashCount; i++)
        {
            sr.color = new Color(1, 1, 1, 0); // Transparente
            yield return new WaitForSeconds(flashDuration);
            sr.color = new Color(1, 1, 1, 1); // Visible
            yield return new WaitForSeconds(flashDuration);
        }
    }
}
```

- Con async/await:

```csharp title="DamageEffectAsync.cs"
using UnityEngine;

public class DamageEffectAsync : MonoBehaviour
{
    private SpriteRenderer sr;
    public float flashDuration = 0.1f;
    public int flashCount = 5;
    private bool isFlashing = false;

    void Awake()
    {
        sr = GetComponent<SpriteRenderer>();
    }

    public async void TriggerFlash()
    {
        if (isFlashing) return;

        isFlashing = true;
        try
        {
            for (int i = 0; i < flashCount; i++)
            {
                sr.color = new Color(1, 1, 1, 0); // transparente
                // destroyCancellationToken cancela la espera si se destruye el objeto
                await Awaitable.WaitForSecondsAsync(flashDuration, destroyCancellationToken);
                sr.color = new Color(1, 1, 1, 1); // visible
                await Awaitable.WaitForSecondsAsync(flashDuration, destroyCancellationToken);
            }
        }
        catch (System.OperationCanceledException)
        {
            // El objeto se ha destruido mientras parpadeaba: no hacemos nada
        }
        finally
        {
            isFlashing = false;
        }
    }
}
```


En ambos casos, para probarlo desde el PlayerController (usando la versión que hayamos añadido al objeto, `DamageEffect` o `DamageEffectAsync`):

```csharp title="PlayerController.cs"
void Update()
{
    if (Input.GetKeyDown(KeyCode.D))
    {
        GetComponent<DamageEffectAsync>().TriggerFlash();
    }
}
```

:::warning[Diferencias importantes con las corrutinas]
- Una corrutina se detiene sola al destruir o desactivar el GameObject. Un método `async` **no**: si el objeto se destruye durante un `await`, al continuar intentará acceder a un objeto que ya no existe y dará error. Por eso en el ejemplo pasamos `destroyCancellationToken`, que cancela la espera cuando se destruye el objeto.
- Los métodos `async void` no pueden esperarse desde otro método y sus excepciones son difíciles de capturar. Solo deben usarse como punto de entrada (por ejemplo, en un método llamado desde un botón). Para métodos asíncronos que llamamos desde otros, se devuelve `Awaitable` o `Awaitable<T>`: `async Awaitable CargarNivelAsync()`.
:::

### Ventajas de la versión async/await

| Moderno (`async`/`await`) | Clásico (`IEnumerator`) |
|---------------------------|-------------------------|
| Se llama como un método normal | Requiere `StartCoroutine()` |
| Usa `await Awaitable.WaitForSecondsAsync()` | Usa `yield return new WaitForSeconds()` |
| Puede devolver un valor (`Awaitable<T>`) | No puede devolver valores directamente |
| Permite capturar excepciones con `try-catch` alrededor de los `await` | No permite `yield return` dentro de un `try` con `catch` |
| Se integra con otras APIs asíncronas de C# (ficheros, red...) | Solo funciona dentro de Unity |
| Hay que gestionar la cancelación (`destroyCancellationToken`) | Se detiene sola al destruir o desactivar el objeto |

Hay que tener en cuenta que:

- Aunque esta API es más moderna, la gran mayoría de tutoriales y ejemplos siguen usando `IEnumerator`, por lo que es imprescindible conocer ambas.

- `Awaitable` ofrece esperas equivalentes a las de las corrutinas: `NextFrameAsync()`, `WaitForSecondsAsync()`, `FixedUpdateAsync()` o `EndOfFrameAsync()`, además de `BackgroundThreadAsync()` y `MainThreadAsync()` para mover trabajo pesado a otro hilo y volver al principal.

- [Documentación oficial de Awaitable](https://docs.unity3d.com/Manual/async-await-support.html)
